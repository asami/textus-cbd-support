# Contextual editing client

`ModelEditPalette` owns contextual applicability and presentation metadata over
the accepted ten command kinds. Context identifies the surface, exact scope and
typed semantic subject. Palette output captures the selected session/candidate
and admitted authorization reference; it is a read result, not a new grant.
Explicit Mono-Koto and Event Storming selections use their existing projection
identities. All surfaces converge on the same subject semantics.

`ModelEditModelMutation` checks the offered command kind and exact contextual
endpoints before calling the existing immutable candidate service. This avoids
an authorized command selected for one Slice or Use Case being applied through
another subject's Palette. The service remains the sole mutation owner. The
adapter receives supplied operation, candidate and Slice successors and returns
the updated session with a shared candidate View. It owns no identity allocator,
reference resolver, approval, canonical writer or external ticket client.

`ModelEditWebView` renders Palette entries and candidate confirmation as escaped
HTML over these immutable values. The direct semantic adapter is callable by the
host; transport and external client exposure keep their later Phase owners.
Confirmation retains the canonical source and exact candidate history, including
independent Specification/Ticket links and capability evidence availability.
Unlinking a selected relationship may remove that subject; the result confirms
the change without inventing a replacement selection or new authority.

Existing source model, package, versioned session codecs and Phase 10 gates are
reused without schema changes. No new stored editing model, Job, AI service,
hash/CAS/replay protocol or source-owner mutation language is introduced.

# Scoped quality review

Author: ASAMI, Tomoharu. Since: Oct. 17, 2026. Version: Oct. 26, 2026.

## Evaluation ownership and execution separation — adopted 2026-10-18

[Phase 15](../phase/phase-15.md) owns the evaluation semantics below.
[Phase 15.1](../phase/phase-15.1.md) separates preparation/external-result
acceptance from execution under the
[execution contract](scoped-review-execution-contract.md). This is an adopted
target, not a claim that the new APIs are implemented. R3's AiRunner path describes
the existing implementation and the retained explicit standalone execution role;
it must not be imposed on the new orchestrated route. Both routes share R1/R2/R4
evaluation meaning. External execution attribution follows E3 of that contract,
without fabricating the SPI metadata used by the existing standalone path.
R5's consumer ownership remains: CBD results do not grant Admission or commits.

For affected-scope re-evaluation, the consumer selects the relevant checks and
context; CBD applies the same rules and retains applicable attributable finding
identities. Unrelated results are not invalidated by a lifecycle label or commit.
Reuse/applicability decisions belong to the consumer, not a new CBD cache/replay
engine. Existing focused specs remain evidence only for their implemented route.

The private `CbdReviewAdmin.reviewScopedQuality` QUERY evaluates explicitly
selected checks over supplied bounded materials. Its typed CML request and
result are generated by the ordinary Cozy build. Rule revision is
`cbd-scoped-quality-v1`.

## R1: Request and selected scope

The request carries caller-owned `reviewId`, positive long `revision`,
`subjectId`, and `subjectRevision`. IDs and revisions are ordinary declared
references, never derived from material bytes. IDs are nonblank, at most 128
characters, and contain no control characters. Scope selects at least one
relative path label or exact model subject; labels are nonblank and at most
1024 characters. Absolute paths and parent escapes are rejected. Labels are
never opened as files.

Every repeated input collection is limited to 64 entries. Each material is at
most 262144 UTF-8 bytes; materials and requirements together are at most
1048576 bytes. Material kind is one of `source`, `diff`, `requirements`, or
`cml-metadata`. Optional material path/model subject must be in selected scope.
Checks are nonempty, unique, and drawn from `cml-contract`,
`semantic-consistency`, `implementation-quality`, `excessive-checks`, and
`integration`. Invalid input fails with a typed Consequence before AI execution.

Executable examples: [S1 and S5](../../src/test/scala/org/simplemodeling/textus/cbdsupport/ScopedQualityReviewProviderSpec.scala),
[O1 and O2](../../src/test/scala/org/simplemodeling/textus/cbdsupport/ScopedQualityReviewOperationSpec.scala).

## R2: Bounded CML structure

`cml-contract` consumes exactly one supplied `cml-metadata` material declaring
`cozy.cml.model-metadata.v1`. It selects subjects by exact declared `termId`
across surface component, services, operations and model elements. It does not
infer subject links from names. It examines selected declarations and their
declared field/input/output relationships. Required operationType/inputType/
outputType or field name/type omissions yield a structured blocker identified
by `cml.declaration.incomplete`. Malformed metadata fails evaluation.

Only declared type references link related declarations. Unresolved external
types, absent metadata or missing/ambiguous subjects remain unsupported.
Covered model subjects establish this bounded structural rule only. The result
does not infer CML-derived path coverage, semantic quality or global lint
completion. Deterministic-only requests do not invoke AI; provider ID is
`cbd-scoped-quality` with no semantic purpose or model.

Executable examples: [S2, S3 and S4](../../src/test/scala/org/simplemodeling/textus/cbdsupport/ScopedQualityReviewProviderSpec.scala).

## R3: Actual semantic execution and provenance

Each CBD component owns a fresh optional AiRunner input socket set. Ordinary
CNCF SPI bootstrap installs providers; unrelated operations require no AI.
The same component Port publishes one
`AiRunnerApplicationPurposeRegistration` for
`car-review.semantic-consistency`, with default standard purpose
`software-analysis` and an empty provider-neutral default policy. Textus AI
collects it through `AiRunnerApplicationPurposeRegistrationSocketSet` during
normal bootstrap. The selected deployment profile owns concrete model/provider
selection and effective policy; the registration supplies no tools, execution
class, timeout or policy bounds. Application-purpose configuration tunes this
registered name and cannot create its registration.
Within `ProviderCall.build_Program`'s provider step, semantic checks resolve
that installed socket and call `AiRunner.generateRecord` once using the current
ExecutionContext, required purpose `car-review.semantic-consistency` and no
tools. There is no default-provider or advisory API fallback.

The prompt contains bounded selected scope, requirements, materials and
deterministic outcomes. It requests focused consistency against requirements,
implementation quality, excessive assurance and integration only as selected.
Before the untrusted payload, a labelled output-schema section includes the
same JSON schema supplied in `AiRecordRequest.schema`, so prompt-only providers
receive the existing response contract. The prompt requires exactly one JSON
object without prose or Markdown. Required arrays remain present, using `[]`
when empty: top-level `checks` and `findings`, and each check's `paths`,
`modelSubjects` and `limitations`. Covered scope must match the selected inputs,
and target identity/revision must be preserved.
Supplied source text is review data, never an instruction or executable tool.
Provider ID and model come from actual response metadata/model. Missing
attributable provider metadata prevents covered semantic evidence. Missing SPI
or unavailable purpose/provider is an explicit gap; execution failure is failed.
Provider traces contain only ordinary review identity and counts. Provider
result attributes are empty; source, prompt, diff and findings are not logged
by this provider. AiRunner retains its own normal tracing/redaction policy.

Executable examples: [S1, S1a, S3 and S5](../../src/test/scala/org/simplemodeling/textus/cbdsupport/ScopedQualityReviewProviderSpec.scala),
[O1 and O3](../../src/test/scala/org/simplemodeling/textus/cbdsupport/ScopedQualityReviewOperationSpec.scala).

## R4: Findings, coverage and failure

Semantic output echoes `reviewId`, `revision`, `subjectId` and
`subjectRevision` and accounts for exactly the selected semantic check IDs.
These are the references of the current request, including a request for
affected-scope re-evaluation. A response for a previous review revision cannot
complete that current request. Each check uses `covered`, `unsupported` or
`failed`, with scope within the request. Covered semantic checks must account
for all selected paths and model subjects; partial scope becomes unsupported
with an explicit limitation. Unsupported/failed output may carry limitations.
Findings carry ordinary identity, requested check, severity (`blocker`,
`hygiene`, `development-candidate`), selected path and/or model subject, and
message. Contradictory, malformed, wrong-target or out-of-scope output fails
evaluation. Zero findings is a valid clean result. Semantic output cannot
replace deterministic findings.

The result echoes admitted target references. It is `completed` only when
every requested check is covered, `failed` if any check failed, otherwise
`unavailable` for any unsupported coverage. Completed describes evaluation
coverage even when blocker findings exist. It grants no Admission or commit
permission and has no evidence-trust bit or workflow state.

Affected-scope re-evaluation uses the same ordinary Operation with the caller's
current review/subject references and explicitly selected checks and materials.
CBD returns only those checks and preserves the supplied finding identity and
scope when that finding remains applicable. It does not reconstruct prior
results, invalidate unrelated findings, or decide which earlier evidence the
consumer may reuse.

Executable examples: [S1–S4](../../src/test/scala/org/simplemodeling/textus/cbdsupport/ScopedQualityReviewProviderSpec.scala)
and [O4](../../src/test/scala/org/simplemodeling/textus/cbdsupport/ScopedQualityReviewOperationSpec.scala).

## R5: Private operation and consumer responsibility

The generated QUERY resolves the handwritten factory ActionCall and normal
provider/UoW path. `CbdReviewAdmin` remains absent from MCP-ready services. The
existing managed-effects query remains usable without AI.
O3 exercises ordinary SPI collection of the purpose registration alongside the
factory-created CBD component, including its optional AI input. It establishes
bootstrap wiring only; it does not claim a real provider execution. An absent
runtime or unavailable purpose/provider still produces an explicit gap through
R3, with no fallback.

sm-workflow, as consumer, owns its CAM: selection of review target and scope,
requirements and supplied materials, interpretation of findings and coverage,
Evidence and Admission decisions, lifecycle transitions, and local commit
authority. CBD evaluates the supplied scope only. This addition creates no
workflow state, effect authority, file/process/HTTP access, configuration
parser, or separate audit store. Existing historical review APIs are separate
and are not a fallback for this contract.

Executable examples: [O1–O3](../../src/test/scala/org/simplemodeling/textus/cbdsupport/ScopedQualityReviewOperationSpec.scala).

The component's ordinary generated model must compile and preserve nested Entity
values through its declared-store bindings. G1 in the same Operation specification
qualifies the actual generated `ReviewDiagnosis.targets` binding with populated
framework attributes, including Slug, Charset and URL. Roundtrip preserves those
values; malformed scalar JSON fails decoding. This regression qualifies the
generation dependency and does not claim external review execution or Admission.

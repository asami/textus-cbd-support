## Authored boundary

The registered provider execution path previously returned admitted metadata
without its actual provider body. CBD1 retains the successfully admitted bounded
bundle with that metadata as the existing `AdmittedProviderBundleInput`, so the
additive canonical API can hand the real input to the existing canonical response
application. The application still selects the registered descriptor and crosses
CNCF ProviderCall. Legacy public method signatures, constructors, patterns and
named arguments remain intact.

The single process-local admitted cache now uses explicit Review ID and provider
identity. It stores no new control hash, byte-comparison identity, second cache,
or authoritative persisted provider-body store. Existing provider wire digest
fields and their bundle admission remain unchanged; they do not identify cache
entries. This slice introduces no new digest mechanism or exception approval.

Request schema/shape and outer Review/target binding are checked before provider
execution or cache access. Quality preflight and registered descriptor selection
retain their priority. Cached input is re-admitted against the current envelope
and appropriate policy. Refusal remains attributable, returns no body, and never
reruns the provider. Successful re-admission refreshes metadata while retaining
the same bundle. An immutable same-Review/provider request with a changed limit
is refused by existing request binding admission. The canonical handoff invokes
the legacy path once, preserves refusal verbatim, and returns retained input and
the original `fromCache`; missing input is attributable
`provider-canonical-input-missing`/`failed`/`runFailure=true`.

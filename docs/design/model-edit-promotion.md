# Model Edit confirmation and existing promotion owners

ModelEditConfirmation binds the exact editing session and source rendering to the
existing Phase10 candidate/source mapping/semantic diff and complete subject. It
prepares an ordinary scoped ReviewRequest and a readable inventory; it grants no
approval or write permission. Preparation retains actual producer observations and
the exact candidate artifacts so independent review and the human can assess them.

ModelEditPromotion delegates only after existing separately admitted review and
actual-human approval inputs are available. It never constructs an Approved input,
copies fixture authority into a real run or treats the semantic Step result as a
product decision. Existing typed human-approval, continuation, lifecycle/freshness
and CML-change application owners retain all checks and actual file effects.

Preparation and canonical application have separate explicit inputs. Missing review
or human input stops the declared E2E qualification with retained artifacts and no
canonical writes. The same native workflow continues after the genuine missing
input is supplied; there is no new helper-specific workflow or acceptance cycle.


`ModelEditPromotion.Inputs` composes existing independently admitted execution basis,
actual Human input, selected Approval artifact, exact source-owner authority and live
source observations. `admitAndApply` uses the existing file-backed human validator,
then builds the ordinary continuation request for the exact candidate's complete
mapping set and calls the existing canonical owner. It creates no approval. The
normal host remains responsible for genuine attribution; portable JSON is not an
authenticity proof. Missing or unrelated inputs cannot become canonical permission.

The integration adapter first prepares a retained target, then separately consumes
supplied ordinary records at that target. It uses the selected proposed source's
actual producer re-observation for model-context freshness and the canonical
owner's existing-file CML observation for the predecessor baseline. Current review
and Human input must bind the same full typed subject, including the captured
existing Specification. The inherited ordinary helper is reused without changing
its accepted source; the Stage12.7 adapter explicitly extends its Goal-only diff to
all actual added elements and independent trace edges. Unknown compatibility and
migration effects remain subject to genuine independent review, not implicit safe
values. The source-owned confirmation renderer exposes Actor Goal, Event Storming,
Slice/Specification/Ticket traces and demand availability for the same candidate.

The native check selects a retained absolute root only after a genuine first
preparation. Missing independent records produce a real missing-input failure with
that root retained. Normal native continuation owns qualification after actual input
is supplied. This is one existing execution path, without a new approval workflow,
persisted model, helper acceptance cycle or source-owner bypass.

The actual ApplicationReport remains a local value in the same E2E JVM through
required post-validation. The adapter executes the explicitly selected installed
Cozy launcher with the existing exact runtime/target lint argv and retains its
terminal outputs. It independently produces the applied source and calls the
existing canonical projector using the previous explicit witnesses. New artifact,
record and baseline references are caller-declared; neither content nor collection
order allocates them. `ModelEditPromotion.validateApplied` composes the existing
post-validation owner; failed or unavailable evidence prevents a passing E2E.

The original complete reviewed candidate carrier moves intact to ordinary retained
review material before the active package is replaced by the refreshed canonical
carrier. This keeps original edit/history dependencies exact instead of silently
rebinding them to a new source snapshot. The historical package and current canonical
package have separate purposes. Stage12.8 consumes their real typed artifacts and
existing continuation owners. The readable post-validation summary is an observation,
not a serialized application capability or a new persistence protocol. Successful
post-validation remains ReprojectedPendingAcceptance pending actual repository
acceptance.
